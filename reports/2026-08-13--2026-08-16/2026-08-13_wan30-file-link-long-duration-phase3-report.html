核心结论

长时输出证明 Wan 3.0 能持续消费 PDF、PPTX、DOCX、XLSX、Markdown 与网页，但“生成得更久”不等于“理解得更准”。生产判断必须把接口成功、媒体健康与事实保真分开。

01 / OUTPUT

不再只有 2 秒

本轮固定生成 15、20、30 秒视频；两个 duration=-1 输入分别选择 20 秒和 30 秒，说明智能时长会随输入变化。

02 / SEMANTICS

结构化视觉文件更可靠

PPTX、图片 DOCX、图表 XLSX 与扫描 PDF 的主题和主要视觉对象相关性最好，其中 30 秒产品 PPTX 内容覆盖最完整。

03 / FIDELITY

长时没有消除幻觉

Markdown 出现错误命令和拟制登录页；API 网页与 React 官网均被改造成源站不存在的产品界面，文字和品牌字样不稳定。

04 / MOTION

唯一帧不等于持续运动

所有帧 MD5 都唯一，但 XLSX 20 秒累计近静止 12.73 秒，Markdown 15 秒累计 10.10 秒。细微压缩变化会掩盖视觉冻结。

05 / RETRIEVAL

第三方取件不稳定

同一 jsDelivr PDF 可先失败后成功；网页解析也出现首次失败、重试成功。URL 尾段扩展名和特殊字符会直接改变结果。

06 / LIMITS

50 页 PDF 上限已在线确认

52 页 PDF 创建后快速失败，错误明确为 PDF page count (52) exceeds limit of 50。平台应在付费任务前完成页数和格式预检。

Production Gate

保留 file/link Shadow；先做自有稳定 URL 转存、有限重试、逐帧 OCR/数字核验与近静止检测，再讨论默认路由。

固定时长 vs 智能时长

duration=-1 能自动选择长度，但没有证据表明它会自动提升事实准确性、叙事完整度或运动质量。它应被视为长度选择器，而不是质量优化器。

检测口径

freezedetect=n=-50dB:d=0.3 捕捉近静止，而非编码重复帧。因此“600/600 唯一帧”和“累计近静止 12.73 秒”可以同时成立。生产验收不能只看帧哈希。

URL 与文件边界

正向任务成功不代表第三方资源可被稳定消费。格式判断、特殊字符、页数限制、重定向和 Provider 侧下载抖动都应在平台 Adapter 层被吸收。

01

扩展名必须可识别

https://arxiv.org/pdf/1706.03762 被判定为扩展名 03762；即使响应 MIME 为 PDF 也失败。

02

@ 会被拒绝

media.url 含 @ 会明确失败，常见的 repo@version CDN 形态不能直接传入。

03

PDF 最多 50 页

52 页文档创建后快速失败，错误明确为 PDF page count (52) exceeds limit of 50。

04

下载存在非确定性

同一 jsDelivr PDF 首次失败，随后固定 30 秒与智能时长任务均成功；网页解析同样出现重试成功。

05

Raw URL 不够稳定

GitHub Raw PDF 多次报 Failed to download，添加 ?download=1 也没有改善。

06

平台应先转存

先下载并验证魔数、页数和大小，再转存到扩展名明确、不含特殊字符的自有 HTTPS URL；失败重试必须幂等。

前置资产治理

验证真实格式、页数和文件大小，统一转存自有稳定 URL，屏蔽第三方链接形态差异。

内容级验收

技术文档、命令、数字、品牌文字必须做逐帧 OCR 与源内容比对，主题相关不能替代事实准确。

媒体级验收

保留完整解码、黑帧、音轨检查，并新增 near-static 占比门槛；不要用唯一帧计数替代运动判断。

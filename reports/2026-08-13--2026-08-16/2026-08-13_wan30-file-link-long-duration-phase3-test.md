# Wan 3.0 文件与网页长时输入 Phase 3 实测

**日期：** 2026-08-13  
**模型：** `wan3.0-video`  
**配置：** `480P / adaptive / audio=false / watermark=false`  
**主测试：** 10 条实际生成视频，覆盖 15-30 秒固定时长与两个 `duration=-1` 对照。

## 1. 结论

本轮不再是 2 秒 smoke。10 个主测试全部产出并下载了真实 MP4，总输出 235 秒：15 秒 1 条、20 秒 5 条、30 秒 4 条。两个智能时长输入分别选择论文 20 秒、网页 30 秒，证明 `-1` 会按输入变化，不是固定返回最大时长。

接口层通过，生产质量仍未通过：

- 长时 file/link 可以稳定产出 H.264 832x480/30fps 视频；10 条均可完整解码、无音轨、无黑段，每帧 MD5 均不同。
- PPTX、图片 DOCX、XLSX、扫描 PDF 的主题和主要视觉对象相关性较强；30 秒 PPTX 覆盖三种配色、结构拆解与使用场景，明显优于此前 2 秒摘要。
- 长时没有解决事实幻觉。Markdown 15 秒把源文扩写为大量命令、登录页、API Key/Token Plan 页面和提示，其中可见多条错误或乱码命令；网页 30 秒两版都生成了大量拟制控制台/UI。
- 长时没有解决静态停顿。XLSX 20 秒累计约 12.73 秒近静止，Markdown 约 10.10 秒；论文固定 30 秒约 6.63 秒，智能 20 秒约 7.53 秒。唯一帧计数仍会被细微压缩变化误导。
- `file` 取件具有明显 URL 形态和非确定性风险。同一 jsDelivr PDF 第一次报下载失败，随后固定 30 秒和 `-1` 都成功；GitHub Raw 多次失败。URL 尾段无 `.pdf` 会被当成错误扩展名，含 `@` 会同步后置拒绝。
- PDF 的 50 页上限已在线验证：52 页文档创建后快速失败，错误明确为 `PDF page count (52) exceeds limit of 50`。

生产裁定保持不变：`file/link` 只能继续 Shadow，不能因 10/10 主结果成功就加入默认生产路由。

端到端时长按 Provider `submit_time -> end_time` 计算。网页固定 30 秒的 25m53s 包含约 10 分钟排队；论文固定 30 秒无显著排队但执行约 26 分钟。输出时长不能作为前台等待时长的代理。

## 3. 固定时长与智能时长

### 3.1 论文：`30s` vs `-1 -> 20s`

两版都从源论文提取了流程图、trace tree、代码和性能图，证明模型不是只读首页。固定 30 秒版增加标题开场和结论页，但标题、代码和结论文字存在较多乱码；智能 20 秒版直接进入算法图，视觉更紧凑，也没有获得更高事实保真。

媒体层面，固定版累计冻结占 22.1%，智能版占 37.7%。智能时长节省 10 秒、约 ¥3，但不是质量优化器；它只决定成片长度。

### 3.2 网页：`30s` vs `-1 -> 30s`

智能时长仍选择满 30 秒。固定版重点展示输入框、首尾帧、分辨率与 2-30 秒；智能版覆盖文生、图生、参考生、分辨率、时长和 PENDING/RUNNING/SUCCEEDED 状态，信息范围更广。

两版都大量使用源网页不存在的产品化界面，并出现 `WAN/WNW` 等不稳定品牌字样。因此 `-1` 不能作为“自动生成更完整且更真实的视频”承诺，只能写为 Provider 自动选择长度。

## 4. 内容质量

### 4.1 相对可靠的输入

- **PPTX：** 30 秒完整覆盖了四页中的产品外观、三种配色、拆解结构和佩戴场景，且无冻结，是本轮最接近可用产品摘要的样本。
- **图片 DOCX：** 三张实际图片均被识别，主题没有漂离。问题主要是尾部 3.1 秒近静止。
- **图表 XLSX：** 年份、Revenue 和品类图例总体相关，能把多图表转成线图、饼图和柱图序列。但数值标签小且生成式重绘，不适合作为精确财务陈述。
- **扫描 PDF：** 能从图像页识别书页、插图和折线图，且没有冻结；但只覆盖部分页面类型，不能据此宣称 6 页都被理解。

### 4.2 高风险输入

- **技术 Markdown：** 源文包含 npm 安装、npx skills、浏览器登录、普通 API Key 和 Token Plan 等真实内容，视频并非全是凭空编造；问题在于它把文档重绘成了不稳定终端与登录界面，出现多条错误/乱码命令和拟制页面。技术操作类视频必须逐帧 OCR 与命令比对。
- **长 API 网页：** 两版都抓住了 Wan 3.0、输入类型、分辨率、时长和状态流，但视觉表达基本是模型自创 UI。主题关联通过，页面复刻和事实严格保真不通过。
- **React 动态页：** React 标志和 “web and native user interfaces” 相关；随后出现自创视频搜索站和大会人群，不能解释成对官网内容的完整摘要。
- **论文：** 跨页覆盖成立，但标题、图中文字和结论文字不稳定。适合做研究主题意象，不适合未经复核地传播论文结论或性能数字。

## 5. 媒体检查

10 条主结果均为 H.264、832x480、30fps，无音轨，可完整解码，无 blackdetect 事件。帧数与时长严格对应：15s=450 帧、20s=600 帧、30s=900 帧，且每帧 MD5 均唯一。

冻结检测使用 `freezedetect=n=-50dB:d=0.3`。该指标捕捉的是近静止，不代表编码重复帧；这正是“600/600 唯一帧”和“12.73 秒近静止”能同时成立的原因。

| Case | 冻结次数 | 累计 | 最长 |
|---|---:|---:|---:|
| XLSX 20s | 22 | 12.73s | 1.90s |
| Markdown 15s | 13 | 10.10s | 1.97s |
| 论文 `-1` 20s | 19 | 7.53s | 0.90s |
| 论文固定 30s | 11 | 6.63s | 1.43s |
| 图片 DOCX 20s | 2 | 4.27s | 3.10s |
| 网页 `-1` 30s | 3 | 1.37s | 0.57s |
| 网页固定 30s | 2 | 0.60s | 0.30s |
| PPTX / 扫描 PDF / React | 0 | 0 | 0 |

## 6. URL 与文件合同边界

为完成正向 PDF 测试，本轮额外留下 13 个无输出失败任务和 1 个额外 20 秒 PDF 正例。失败任务 `usage` 为空，不把它们计入成功视频费用；是否存在其他账单项仍以百炼账单为准。

可复现边界：

1. `https://arxiv.org/pdf/1706.03762` 被判定为扩展名 `03762`，即使响应 MIME 为 PDF 也失败；文件 URL 需要 Provider 能从尾段识别合法扩展名。
2. `media.url` 含 `@` 会被明确拒绝；常见 CDN 的 `repo@version` 形态不能直接传。
3. 52 页 PDF 被明确拒绝，线上上限为 50 页。
4. GitHub Raw PDF 多次报 `Failed to download`；加 `?download=1` 仍未改善。
5. 同一 jsDelivr TraceMonkey PDF 首次固定任务下载失败，随后同 URL 的 `-1` 和固定任务均成功，证明取件失败有非确定性成分。
6. 同一官方网页第一次 `-1` 报解析失败，重试成功并输出 30 秒；网页解析同样不是稳定的前置事实。

平台必须先下载、验证魔数/页数/大小，再转存到不含特殊字符、扩展名明确的自有稳定 HTTPS URL；对 Provider 下载/解析失败做有限重试和幂等计费，而不是把第三方 URL 直接当稳定资产。

## 7. 成本与产物

10 条主测试总输出 235 秒，按 `480P ¥0.3/s` 估算 ¥70.5，低于确认时的 ¥73.5 最坏预算。替换 PDF 源时额外成功生成了一条 20 秒社区服务 PDF，增加约 ¥6，因此本轮成功视频总估算为 **¥76.5**。这是执行替换样本造成的超预算，单独披露，不纳入 10 条主结果。

主测试 MP4 共约 126.1 MB；所有任务元数据、失败证据、MP4、逐秒帧、contact sheet、ffprobe、黑帧和冻结日志位于：

```text
analysis/wan30-long-input-2026-08-13/
```

凭据、Authorization Header 和临时 `video_url` 均未写入产物。

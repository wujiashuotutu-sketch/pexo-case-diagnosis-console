# MiniMax H3 音频控制 API 实测

测试日期：2026-08-13（Asia/Shanghai）

## 结论

MiniMax H3 V2 创建接口没有文档化的输出音频开关。所有本轮产物都包含 AAC 音轨，包括要求完全静音的任务。

- Prompt 可以明显引导静音、音效、对白和音乐，但属于概率性内容控制。
- 未文档化的顶层 `sound: true/false` 会被接口接受，但不能关闭或强制开启声音，不应作为生产参数。
- 冲突测试中，`sound:false` + 明确音乐 Prompt 仍生成全程高响度音乐；`sound:true` + 绝对静音 Prompt 仍接近数字静音。结果表明 Prompt 的影响明显强于该未知字段，该字段很可能被忽略。
- 严格无声必须在生成后删除音轨或替换为静音轨，并执行确定性音频检查。

## 测试范围

模型和规格统一为：

- `model`: `MiniMax-H3`
- `resolution`: `768P`
- `duration`: `4`
- `ratio`: `16:9`
- 固定画面：红色纸飞机从左向右飞过白色摄影棚背景

共新增 12 条任务。所有任务均成功，所有文件均为约 4.46 秒视频，并包含约 4.45 秒的 AAC、32 kHz、双声道音轨。

指标说明：

- `LUFS`：综合响度，数值越接近 0 越响。
- `Peak`：最高峰值。
- 静音占比：使用 `silencedetect=noise=-50dB:d=0.15` 统计，按 4.48 秒音频时间轴计算。
- 接近数字静音：本报告中指约 `-70 LUFS`、峰值低于 `-76 dBFS`、静音占比 100%。

## 参数裁定

### 文档化参数

`/v2/video_generation` 的公开 schema 没有 `sound`、`audio`、`enable_audio` 或 `mute` 字段。

`content[].audio_url` + `role=reference_audio` 是参考音频输入，用于全能参考生成，不是输出音频开关，也不保证原音轨透传。

### 未文档化 `sound` 字段

服务端接受未知顶层字段不能视为能力证明。严格冲突测试说明：

1. `sound:false` 无法压制明确音乐 Prompt。
2. `sound:true` 无法覆盖明确静音 Prompt。
3. 相同音效 Prompt 的 `false`、未传、`true` 三条任务均生成声音，响度差异落在生成随机性可解释范围内。

因此当前 Adapter 应只传公开 schema 字段，不应把业务层 `sound` 原样传给 MiniMax H3。

## 推荐控制策略

### 需要模型原生声音

在 Prompt 中明确写出声音对象、时间、强度和排除项，例如：

```text
Audio: generate a clearly audible paper flutter and airy whoosh synchronized
with the airplane movement. No speech and no music.
```

这能提高生成相应声音的概率，但生成后仍需检查音轨存在、响度和内容是否符合要求。

### 要求严格无声

Prompt 中声明绝对静音只能作为生成偏好。交付前应执行：

```bash
ffmpeg -i input.mp4 -map 0:v:0 -c:v copy -an output.mp4
```

并确认输出不存在音频流：

```bash
ffprobe -v error -select_streams a -show_entries stream=index -of csv=p=0 output.mp4
```

预期输出为空。

### 业务字段建议

业务层可以继续保留 `audio_mode`，但应由 Adapter 和后处理解释：

- `native`: Prompt 编译声音描述，生成后做音频 QC。
- `silent`: Prompt 写静音偏好，生成后强制删除音轨。
- `external`: 不依赖 H3 原生声音，生成后移除原音轨，再混入已锁定音频资产。

不要把这三个业务值编译成 MiniMax H3 的 `sound` 字段。

### 稳定性判定

- 绝对静音 Prompt：2/3 次（66.7%）达到接近数字静音，1/3 次出现明显短音频。
- 明确音乐 Prompt：3/3 次（100%）生成全程可测音乐。
- `audio:false`、`enable_audio:false`、`mute:true`：3/3 次均未阻止音乐。

这轮重复结果把控制边界进一步收窄：H3 可以较稳定地按 Prompt 生成音乐，但不能稳定保证静音。需要严格音频合同时，必须在 H3 输出后执行确定性 `-an` 或静音混音处理，不能依赖 Prompt 或未知字段。

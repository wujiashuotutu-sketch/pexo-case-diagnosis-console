## 核心结论

1. `reference_audio` 在 H3 中实际会强烈影响甚至直接保留到最终音轨。无用途声明、对白、口型、click、marker 和带原音视频冲突都出现了显著的参考波形相关性。
2. Prompt 中的“忽略音频”“只作节奏/marker”“不要输出 click/marker”“独立音频是唯一对白来源”都不是可靠的最终音轨控制。静音人声 3/3、静音 click 3/3、静音 marker 3/3 均保留可听音轨。
3. 带原音视频时，H3 更偏向源视频的嵌入音频（`0.8075`），不能把独立 `reference_audio` 当作强制覆盖；需要 Adapter 明确拆分视觉参考和音频后处理。
4. 当前正式样本没有证明严格逐字 ASR、音色相似度或 `250ms` 逐帧口型同步；这些结论必须在有时间戳 ASR、口型检测和盲听人工评测器后再下判断。
5. 生产侧若要严格静音、只保留某一外部音轨或移除参考 click/marker，应在 Provider 输出后执行确定性的音轨替换/删除和 `ffprobe`/PCM 验收，不能依赖 H3 的 Prompt 软控制。

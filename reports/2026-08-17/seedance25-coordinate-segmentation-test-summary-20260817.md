# Seedance 2.5 坐标与分割参考测试结论

日期：2026-08-17  
模型：`doubao-seedance-2-5-260628`

## 1. 测试问题

将坐标标记图、目标元素透明分割图，或两者同时传给视频生成模型，是否能提高局部修改的目标命中、元素保持和非目标区域稳定性？

## 2. 测试设计

使用同一张客厅图片，桌面放置两只外观相同的红色杯子。每组 4 秒、720p、无音频。由于模型不开放输入 seed，各组实际随机 seed 不同，因此本轮只能作为单样本 smoke test。

本轮“坐标”指视觉坐标引导图中的红色方框。数值 `bbox_norm` 只保存在本地元数据中，没有写入视频模型 Prompt，也没有作为 Provider 的结构化参数传入。因此本轮验证的是“视觉方框参考”，不是“数值坐标 Prompt”。

四组输入：

| 组别 | 输入 |
|---|---|
| A | 完整图片 |
| B | 完整图片 + 左杯坐标框 |
| C | 完整图片 + 左杯透明分割图 |
| D | 完整图片 + 坐标框 + 透明分割图 |

测试了两个任务：

1. 目标运动：只让左杯上升和轻微旋转，右杯保持不动。
2. 局部修改：只把左杯改为钴蓝色，右杯继续保持红色。

## 3. 结果

### 3.1 目标运动

- A/B/C/D 均正确选择左杯，没有误动右杯。
- 抽样帧粗略像素跟踪显示，左杯上移约 81-114 px；右杯垂直漂移不超过约 1.3 px。
- 四组均未出现坐标框、透明卡片或第三只杯子。
- 基线中间帧出现一次明显高光/光斑，辅助参考组没有同样现象；由于每组 seed 不同，不能归因于坐标或分割。
- 当前任务中 Prompt 的“左侧杯子”已经足够明确，坐标和分割没有显示出目标命中增益。

### 3.2 局部颜色修改

- A/B/C/D 均成功把左杯改为蓝色，右杯全程保持红色。
- 固定右杯区域的抽样帧中未检测到蓝色像素，未观察到颜色串改。
- 四组均未出现坐标框、透明背景、额外杯子或明显场景结构变化。
- 只使用方框的 B/D 与基线和分割组结果接近，没有形成可见质量排序。

早期坐标图同时包含向上箭头，B/D 出现了逐帧变色；移除箭头、只保留方框后，修改从首帧起完成。说明原始标注中的箭头、文字和涂鸦可能被模型解释为运动或内容语义，不能把所有前端标记原样传给视频模型。

### 3.3 数值坐标 Prompt 补测

在 Prompt 中明确加入原图归一化坐标：

```text
bbox [0.316406, 0.536111, 0.147656, 0.219444]
order [x, y, width, height], origin at top-left
```

补测两组：完整图 + 数值 bbox，以及完整图 + 数值 bbox + 透明分割图。

- 两组均正确修改左杯，右杯保持红色，没有坐标文本或额外元素泄漏。
- 数值 bbox 单独输入时，左杯在约前半段逐步从红色变为蓝色。
- 数值 bbox + 分割图从首帧起已经是蓝色，与仅分割图结果接近。
- 相对基线没有观察到目标命中、非目标保持或视觉质量上的明确增益。
- 由于各组随机 seed 不同，这只能说明数值坐标可以被模型接受并没有造成错选，不能证明模型精确使用了 bbox 数值。

## 4. API 约束

Seedance 2.5 返回明确错误：

```text
first/last frame content cannot be mixed with reference media content
```

因此不能在同一次调用中同时使用：

- 完整图片作为 `first_frame`；
- 坐标图或透明分割图作为普通 `reference_image`。

本轮可比测试只能把全部图片都作为普通参考图。这会失去精确首帧锁定，是产品编译层必须处理的硬约束。

## 5. 当前结论

1. 在目标可以通过“左侧杯子”等自然语言明确定位时，增加视觉方框、数值 bbox Prompt 或分割图都没有显示出可见增益。
2. 坐标图不是无害元数据。箭头、文字和涂鸦可能被视频模型当作运动指令或可见内容。
3. 分割图在本轮没有改善目标命中或颜色保持，但可能在具体产品、人物身份、Logo 和遮挡场景中有价值。
4. 不建议默认把前端圈画帧和全部分割元素直接塞给视频模型。
5. 更稳的主链路是：坐标/分割控制 Seedream 5.0 Pro 完成静态局部修改，输出干净的完整修改图，再把该图作为视频模型 `first_frame`。
6. 只有需要特定元素身份保持或独立运动时，才将通过质量检查的元素分割图作为补充视频参考。

## 6. 下一轮有效验证

下一轮应使用自然语言难以唯一定位的困难用例，并每组重复至少三次：

- 三个外观相似对象，只指定中间或被遮挡对象。
- 产品或 Logo 局部替换，检查形状和文字保持。
- 人物服装局部修改，检查脸部和身体未被重画。
- 目标被前景部分遮挡，检查遮挡关系。
- 现有视频编辑：`reference_video + coordinate/segment reference_image`，检查跨帧目标跟踪。

决策指标应包括目标命中率、非目标区域变化率、身份保持、标记泄漏、时序稳定、成本和耗时。只有在困难用例中 B/D 持续优于 A，才值得成为默认路由。

Wan 3.0 能读图、视频、音频、文件和网页，能把结构化资料快速变成视频草稿；但精确文字、事实保真、连续运动和严格口型仍需要后验收。

当前定位

默认生产：暂不建议
本看板将“接口产出”“语义相关”“媒体健康”“生产可交付”分开统计。

场景路由

先看任务类型，再决定是否使用 Wan 3.0。主判断是：创作感和视觉覆盖较强，严格事实和动作精度较弱。

外观、颜色、包装、简单镜头和流程节点有较强样本，适合概念片、SKU 预览和非关键事实的创意草稿。

代表证据：FAB-03、FAB-04、ANM-06，以及产品 PPTX 长时测试。
需 QA 后尝试

角色一致性、参考图生视频、简单物理、简单跟拍

身份和风格通常能延续，但遮挡、手部、高速运动、刚体拓扑和相邻镜头连续性仍可能失真。

代表证据：KAB-05、KAB-07，以及角色 / 参考图输出。
仅供参考

文档、网页、图表、技术资料、复杂空间运镜

主题召回可能成立，但文字、命令、数字、品牌 UI 和空间结构会被模型补写或改写，不能直接作为事实视频交付。

代表证据：中文 Markdown、API 网页、XLSX 图表和 KAB-05 空间穿越。
默认不准入

严格口型、逐帧编辑、精确首尾状态、原音轨逐帧保持

声音或台词正确不等于嘴部连续同步；首尾画面、动作轨迹和原音时间关系目前不能按合同承诺。

代表证据：talking-head drive 的停嘴与后段面部冻结。
Production gate
暂不默认使用

不要因为任务返回 SUCCEEDED 就加入默认路由。Wan 3.0 的不同能力必须拆开过 Gate。

  • 文件 / 网页：先做 URL 可达性、事实召回和 OCR 比对
  • 口播：必须检查嘴部连续运动和音画时间关系
  • 长视频：加入 freezedetect、blackdetect 与人工抽帧
  • 资产：成功后立即转存临时视频 URL

路由建议

把模型能力拆成子能力，避免一个总开关掩盖事实保真或口型问题。

可以继续验证

  • 产品 PPT / 产品图视觉摘要
  • 概念片和非关键事实的创意预览
  • 多模态资料消费后的视觉草稿
  • 有声音但不要求严格口型的短视频

默认阻断或人工复核

  • 技术命令、价格、财务数字和法规内容
  • 网页页面复刻、品牌文字和 UI 事实
  • 严格逐音素口型、原音轨逐帧保持
  • 长视频未经冻结检测直接交付
